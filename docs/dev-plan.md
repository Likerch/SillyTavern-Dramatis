# Dramatis — план разработки

> v1.0 от 2026-10-09. Модель — [`model.md`](model.md) v0.3. Решение: делать все этапы подряд, коммиты от имени владельца, репозиторий GitHub — позже.

## Как работаем
- TypeScript + Vite (библиотечная сборка, `dist/` коммитится), Vitest, ESLint/Prettier, AGPL-3.0, интерфейс ru/en.
- Слои кода и правила — как в Maestro (`docs/ARCHITECTURE.md`): `shared` → `domain` (чистая модель) → `host` (ST) → `core` (сервисы) → `adapters` (соседи) → `ui` → `features` → `app`.
- Один коммит и тег `stage-N` на этап; после этапа — короткий отчёт в чате. Push и прод — только по команде.
- Проверка: юнит-тесты домена (покрытие ≥ 90%); вживую — стенд Maestro (`tools/stand`), Dramatis добавлен соседом.
- Изменения Maestro — отдельными выпусками поверх 1.16.0 (1.17.0 — API и мост; 1.18.0 — крючки генератора и живого мира).

## Ключевые технические решения
- **Хранение:** пользовательские файлы ST с префиксом `dramatis-`: `dramatis-card-<хэш карточки>.json` (личности уровня персонажа), `dramatis-chat-<хэш чата>-<вид>.json` (состояние чата). В метаданных чата — только указатели.
- **ИИ:** с Maestro — через `MAESTRO_API.llm` (профили задач, учёт стоимости, дневной потолок, ведущая вкладка); без Maestro — свой клиент через Connection Manager, только для чтения замысла.
- **События хода:** с Maestro — его `turn:committed`, `reply:ready`, `message:invalidated`; без Maestro проход хода не работает.
- **Вставка:** `dramatis_cast`, глубина 1, system, одноразовая. С Maestro и включённым слиянием — один блок с речью из голосовых карточек; вставки `maestro_voices` и CK гасятся Maestro.
- **Броски:** движок, с внедряемым генератором случайных чисел (тесты детерминированы).
